# 审批矩阵（Copilot 模式）

Phase 0–2：**所有动作默认需人工确认**。下表规定哪些可以更快、哪些绝不能自动。

## 三档

| 档位 | 含义 | 谁执行 | 留痕 |
|---|---|---|---|
| **A** | Agent 可直接执行（几乎无风险、可逆） | Agent | 写入黑板即可 |
| **B** | Agent 出方案，人一键确认 | 人 | 写入 `approvals` |
| **C** | 必须人工决策（花钱 / 压货 / 不可逆 / 有法律风险） | 人 | 写入 `decisions`，含最坏情况 |

> 0→1 阶段默认把 B 当 C 用。宁可慢，不要错。

## 动作分级表

### A 档 — Agent 可直接做

| 动作 | Agent | 说明 |
|---|---|---|
| 采集与整理公开市场数据 | Market | 只读操作 |
| 生成竞品监控清单 | Competitor | 不改任何线上状态 |
| 撰写/改写 Listing 文案草稿 | Store | 草稿不直接上线 |
| 生成短视频脚本与分镜 | Content | 草稿 |
| 生成广告词库（正/否定词） | Ads | 不实际投放 |
| 整理评价与退货归因 | Customer | 只读分析 |
| 更新黑板自己的 namespace | 全体 | 受读写规则约束 |

### B 档 — 出方案 + 人一键确认

| 动作 | Agent | 人工确认要点 |
|---|---|---|
| 调整广告出价（单次幅度 ≤ 20%） | Ads | 确认预算不超日上限 |
| 暂停/启用单个广告词 | Ads | — |
| 新增否定词 | Ads | — |
| Listing 文案上线 | Store | 检查无违禁词、无夸大宣称 |
| 调整售价（幅度 ≤ 10%，且不低于利润底线） | Store | 确认不低于 `finance.unit_profit` 底线 |
| 回复评价/客服模板话术 | Customer | 首次使用需人工过一遍 |

### C 档 — 必须人工决策

| 动作 | 触发条件 | 决策前必须回答 |
|---|---|---|
| **上新 SKU** | 任何 | 首批投入 ≤ ¥3,000？毛利率 ≥ 30%？ |
| **下单备货** | 任何数量 | 最坏情况亏多少？多久回本？ |
| **压货 / 批量生产** | 任何 | 违反 C2，必须双人同意 |
| **日广告预算调整** | 幅度 > 20% | 现金流够烧几天？ |
| **降价** | 幅度 > 10% 或跌破利润底线 | 是价格战还是清库存？ |
| **进入新平台 / 新市场** | 任何 | 违反"先打透一个"原则了吗？ |
| **采购任何付费工具/软件** | 任何 | 免费方案真的不行？验证期多长？ |
| **处理差评索赔、纠纷、退款** | 涉及金额 | 影响账号健康度吗？ |
| **任何涉及认证、专利、商标的动作** | 任何 | 先问 Compliance Agent |

## 放权节奏

不要一开始就放权。按这个顺序，每档至少稳定跑 2 周再考虑下放：

| 阶段 | A 档 | B 档 | C 档 |
|---|---|---|---|
| Phase 0–1 | 开放 | 全部当 C 处理 | 人 |
| Phase 2 | 开放 | 人一键确认 | 人 |
| Phase 3 | 开放 | 小额自动（≤ ¥200/次，日累计 ≤ ¥500） | 人 |
| Phase 4 | 开放 | 护栏内自动 | 人（+ 双人复核大额） |

## 红线（任何阶段都不可放权）

1. 涉及账号安全的动作（改账号信息、申诉、换收款账户）
2. 涉及法律与知识产权的判断
3. 单笔超过 ¥3,000 的支出
4. 任何不可逆的删除操作
5. 以公司名义对外沟通（供应商除外，可用模板）
